# AGENTS.md - Developer & Agent Guide for Ortelana RAG

This document serves as the technical blueprint and operational manual for AI agents and developers working on or evolving the **Ortelana Process Mini RAG** application.

---

## 1. System Overview & Architecture

**Ortelana RAG** is a modular Retrieval-Augmented Generation (RAG) system designed for Ortelana Textil. It allows interactive semantic querying of a textile product catalog with structured validation, real-time sync, and dynamic AI provider switching.

### Tech Stack
* **Language/Runtime:** Python >= 3.13
* **Package & Environment Manager:** `uv`
* **Data Validation & Settings:** `pydantic` v2, `pydantic-settings`
* **Vector Store:** ChromaDB (Standalone Docker container on port 8000, Web UI on 3001)
* **Source of Truth DB:** MongoDB Atlas / Local MongoDB (Collection: `catalogo`)
* **AI Providers:** 
  * **Gemini:** `google-genai` SDK (`gemini-2.5-flash`, `embedding-001` with 768 dimensions)
  * **Cohere:** `cohere.ClientV2` (`command-r-plus`, `embed-multilingual-light-v3.0`)
* **CLI Interface:** Typer, Rich

## 2. Directory & Package Structure

```
src/ortelana/
├── cli.py               # Typer & Rich interactive CLI (/provider, /reload, /sync, /help, /exit)
├── config.py            # Pydantic BaseSettings loading from .env
├── db/
│   ├── chroma.py        # HttpClient for ChromaDB & dynamic collection selection
│   └── mongo.py         # Singleton MongoClient for MongoDB
├── models/
│   ├── product.py       # Domain models: Product, ProductMetadata, LineaTextil
│   └── rag.py           # RAG DTOs: QueryRoute, SearchResult, RAGResponse
├── providers/
│   ├── base.py          # Abstract interfaces: BaseLLMProvider, BaseEmbeddingProvider
│   ├── cohere_provider.py # Cohere implementation (Chat & Embeddings V2)
│   ├── gemini_provider.py # Gemini implementation (google-genai SDK)
│   └── factory.py       # ProviderFactory for dynamic runtime switching
├── rag/
│   ├── router.py        # QueryRouter for intent classification (PRODUCT | DOCUMENT | HYBRID)
│   └── engine.py        # RAGEngine orchestrator (Embed -> Vector Search -> Enrich -> LLM Generate)
└── sync/
    ├── initial.py       # Full sync: Mongo -> Vector Embedding -> ChromaDB Upsert
    └── worker.py        # Real-time sync using MongoDB Change Streams (.watch())
```

## 3. Configuration & Environment Variables

Configurations are managed in `src/ortelana/config.py` using `pydantic-settings`.

Required variables in `.env` (refer to `.env.sample`):
```ini
ACTIVE_PROVIDER=gemini # 'gemini' or 'cohere'

# Gemini Settings
GEMINI_API_KEY=your_gemini_key
GEMINI_LLM_MODEL=gemini-2.5-flash
GEMINI_EMBED_MODEL=embedding-001

# Cohere Settings
COHERE_API_KEY=your_cohere_key
COHERE_LLM_MODEL=command-r-plus
COHERE_EMBED_MODEL=embed-multilingual-light-v3.0

# Infrastructure
MONGODB_URI=mongodb+srv://... or mongodb://localhost:27017
MONGODB_DATABASE=ortelana-app-database
CHROMADB_HOST=localhost
CHROMADB_PORT=8000
```

## 4. Operational Workflows for Agents

### 4.1 Infrastructure Setup
```bash
# Spin up local ChromaDB and ChromaDB Admin UI
docker compose up -d
```

### 4.2 Installing Dependencies
```bash
# Sync environment with uv
uv sync
```

### 4.3 Running Data Synchronization
```bash
# Initial full sync (MongoDB -> ChromaDB)
uv run python -m ortelana.sync.initial

# Real-time change stream worker (listens to MongoDB updates)
uv run python -m ortelana.sync.worker
```

### 4.4 Running the CLI
```bash
# Package entrypoint
uv run ortelana

# Direct module invocation
uv run python -m ortelana.cli
```

## 5. Architectural Patterns & Core Rules

When maintaining or extending this codebase, adhere strictly to these principles:

### 1. Vector Collection Isolation per Provider
* **Rule:** Embeddings generated by different providers (Gemini vs Cohere) exist in different vector spaces and dimensions.
* **Implementation:** `src/ortelana/db/chroma.py` creates collections dynamically as `ortelana_products_{provider}` (e.g. `ortelana_products_gemini`).
* **Do NOT** share collections between providers.

### 2. Provider Abstraction via Factory Pattern
* **Rule:** High-level services (`RAGEngine`, `QueryRouter`, `sync`) MUST interact only with `BaseLLMProvider` and `BaseEmbeddingProvider` via `ProviderFactory`.
* **Dynamic Switching:** Changing provider via `ProviderFactory.set_provider("cohere")` updates active LLM and Embedder across the entire application at runtime.

### 3. Pydantic-First Domain Integrity
* **Rule:** All database documents read from MongoDB MUST be validated using `Product.model_validate(doc)`.
* **Validation Constraints:** Product IDs must match `^TELA-\d{3}$`. Prices must be positive floats. `LineaTextil` is an Enum.

### 4. Control Flow & Style
* **Pattern:** *Never Nested* / Guard Clauses. Prefer `match/case` statement for command routing in `cli.py`.
* **Error Handling:** Catch exceptions gracefully and report using `rich.console`.

## 6. How to Extend the Project

### Adding a New AI Provider (e.g., OpenAI / Ollama)
1. Add settings parameters in `src/ortelana/config.py` (API keys, model names).
2. Create `src/ortelana/providers/<new_provider>_provider.py`.
3. Implement subclass of `BaseLLMProvider` (`generate_response`, `extract_structured`).
4. Implement subclass of `BaseEmbeddingProvider` (`embed_text`, `embed_batch`).
5. Register the new provider in `src/ortelana/providers/factory.py` inside `set_provider`, `get_llm`, and `get_embedding`.

### Adding New RAG Capabilities (e.g. Document Search)
1. Update `QueryRoute` intent handling in `src/ortelana/models/rag.py` and `src/ortelana/rag/router.py`.
2. Extend `RAGEngine.query()` in `src/ortelana/rag/engine.py` to route non-PRODUCT queries to document sources or hybrid lookup.

### Exposing a REST API
1. Create `src/ortelana/api.py` with `FastAPI`.
2. Inject `RAGEngine` into API endpoints (`POST /query`, `GET /products`, `POST /sync`).
3. Add `fastapi` and `uvicorn` to `pyproject.toml`.
